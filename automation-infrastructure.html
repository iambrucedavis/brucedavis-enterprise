PAM Onboarding Readiness

Which accounts are ready for the next rollout group?

Personal project · AI-assisted · Synthetic data · Read-only

Checks whether sample accounts have owners, completed tests, and approval flags before proposing rollout groups. It uses supplied information and does not change accounts.

My contribution: I defined what to check and built the rules, sample account list, report, and tests with AI assistance.

Keep in mind: The tool trusts the sample account information. People still need to check the findings and approve any rollout.

Try this: choose “Blocked” to see what each account is missing.

View example report → View code and tests ↗
Scope and context

The tool checks five supplied fields: account owner, secure credential storage, password-change testing, recovery testing, and change approval. Accounts that depend on each other stay together; if one is blocked, the others wait. The sample has 12 accounts: 6 in 3 proposed rollout groups, 4 blocked, and 2 waiting on dependencies. The optional AI connection was tested with simulated responses, not live AI calls.

The account list supplies the dependencies and approvals. The tool does not find or verify them.

Recorded validation: 24 automated tests passed on November 2, 2026.

Infrastructure Design Validator

What needs attention in this design?

Personal project · AI-assisted · Synthetic data · Read-only

Checks a sample design for selected network, dependency, ownership, and recovery issues. It does not inspect live cloud systems or certify an architecture.

My contribution: I defined the checks and built the sample design, validation rules, system diagram, report, and tests with AI assistance.

Keep in mind: A technical lead still needs to check the supplied design and its assumptions.

View example report → View code and tests ↗
Scope and context

The tool checks the supplied network ranges, system connections, owners, recovery records, selected public ports, and critical systems with only one instance. The sample has 4 components, 3 subnets, and 4 findings. It does not inspect real routing, firewalls, backups, or cloud resources.

All findings come from the sample design. They do not certify a real architecture.

Recorded validation: 12 automated tests passed on November 2, 2026.

Change Readiness Tracker

What is missing from this change plan?

Personal project · AI-assisted · Synthetic data · Read-only

Highlights missing prerequisites and scheduling conflicts, then compares two versions of a change plan. Being ready for review does not mean a change is approved to execute.

My contribution: I defined the checks and built the sample plans, comparison rules, report, and tests with AI assistance.

Keep in mind: The tool does not verify the supplied records or carry out changes.

View example report → View code and tests ↗
Scope and context

The tool checks planned times, shared resources, prerequisites, approval flags, tests, recovery plans, and linked records. It compares two versions of a plan. Four synthetic changes become ready for review after sample corrections. The tool does not verify the records or carry out changes.

A person still needs to check the resources and records before approving work.

Recorded validation: 14 automated tests passed on November 2, 2026.

Read the checks and test criteria ↗

What these prototypes do not do

  • No real accounts or cloud resources are changed.
  • Readiness findings are not approval to execute.
  • Test results and demonstration counts are not customer outcomes.
  • The optional AI connection was tested with simulated responses, not live AI calls.

To run the examples locally, use Python 3.9+ and its standard library. The recorded 50-test run used python3 run_all.py with synthetic scenarios.
